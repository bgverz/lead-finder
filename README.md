# Accredited Investor Lead Generation Pipeline

An automated Python 3.10+ pipeline that identifies, enriches, scores, and exports potential accredited investor leads using public/legal data sources and optional paid API adapters.

Built for pre-IPO / secondary market sales teams selling shares in late-stage private companies.

## What It Does

1. **Targets wealthy zip codes** using Census Bureau income and home value data
2. **Pulls property records** for $2M+ homes from county assessor databases
3. **Identifies business owners** via state corporation filings and OpenCorporates
4. **Finds prior investors** through SEC EDGAR Form D filings
5. **Enriches contacts** through sample data or adapter boundaries for Apollo-style providers
6. **Validates phone numbers** through sample data or NumVerify adapter boundaries
7. **Scores and ranks** every prospect from 0-100
8. **Outputs formatted Excel** sorted by lead quality tier

## Quick Start

```bash
git clone https://github.com/bgverz/lead-finder
cd lead-finder
pip install -r requirements.txt
cp .env.example .env
edit .env
python -m lead_pipeline doctor
python -m lead_pipeline smoke-test
python -m lead_pipeline run --mode mock
```

The expected local run command is `python -m lead_pipeline run --mode mock`.
Use `python -m lead_pipeline doctor` any time you want to check your local setup.

Run modes:

- `mock` / `sample`: offline sample data only.
- `api`: partial-real mode. Uses configured providers such as Apollo, Census, and SEC, and warns/falls back when optional providers like ATTOM or OpenCorporates are unavailable.
- `strict-real`: production readiness mode. Requires all configured production providers, including property and business data providers.

Limit output during API testing:

```bash
python -m lead_pipeline run --mode api --limit 10
```

Apollo search profiles:

- `vc_pe`: venture capital and private equity professionals.
- `founders`: founders and operators.
- `family_office`: family office and private wealth professionals.
- `real_estate`: real estate founders, developers, and investors.
- `healthcare`: healthcare and biotech founders and executives.
- `broad_hnw`: broad investor/founder search.
- `c_suite`: C-level executives at small and mid-sized companies, constrained to roughly 5-500 employees and still using the mega-company exclusions in `config.yaml`.

Example:

```bash
python -m lead_pipeline run --mode api --profile c_suite --limit 50 --open
```

The `c_suite` profile prioritizes ownership/operator, senior executive, financial decision-maker, and technology operator signals. These are inferred from Apollo title and company metadata, not verified interests or accreditation status.

## ATTOM Property Enrichment

ATTOM enrichment uses the trial-compatible address endpoint:

```text
GET /propertyapi/v1.0.0/property/address
Header: APIKey: ATTOM_API_KEY
```

The endpoint requires a usable street address plus ZIP or city/state. The pipeline enriches leads that already have a property address, or Apollo leads when Apollo returns an organization street address. Leads with only city/state/ZIP are marked `needs_address` and are not sent to ATTOM, which avoids wasting paid quota on invalid address lookups.

You can provide addresses separately with `data/input/lead_addresses.csv`:

```csv
name,company,street_address,city,state,zip_code,source
Jane Founder,Example Ventures,12 Round Hill Road,Greenwich,CT,06831,manual_export
```

The CSV matcher uses exact or close name/company matches, fills the street address onto the Apollo lead, and then runs the ATTOM address lookup.

ATTOM adds:

- `property_estimated_value`
- `property_assessed_value`
- `property_type`
- `property_owner_name`
- `property_match_confidence`
- `property_signal`
- `property_lookup_status`
- `property_lookup_reason`
- `address_needed`

High-confidence, high-value matches contribute to property scoring. Tentative matches are exported and summarized, but are deliberately capped so weak matches do not over-score.

### Opening generated workbooks

Open the workbook generated by a single run automatically:

```bash
python -m lead_pipeline run --mode api --limit 10 --open
```

Open only the most recently generated workbook at any time:

```bash
python -m lead_pipeline open-latest
```

> **Warning — do not use shell wildcards:**
> ```bash
> open data/output/investor_leads_*.xlsx   # opens every workbook ever generated
> ```
> Each pipeline run writes a timestamped file, so wildcards expand to all of them.
> Use `open-latest` or `--open` instead.

### Output cleanup

Set `output.keep_last_n_workbooks` in `config.yaml` to automatically delete older
workbooks after each run (default `10`; set to `0` to keep all):

```yaml
output:
  keep_last_n_workbooks: 10
```

## Data Sources

| Source | What It Provides | Cost |
|--------|-----------------|------|
| Census Bureau API | Median income, home values by zip/tract | Free |
| County Assessor / ATTOM | Property values, owner names, sale history | Free / ~$0.10/record |
| State Secretary of State | LLC/Corp filings, officers | Free |
| SEC EDGAR | Form D filings, investor/officer names | Free |
| OpenCorporates | Company records, linked officers | Free (500 req/mo) |
| Apollo.io | Work email, title, company, LinkedIn, phone | Existing subscription |
| NumVerify | Phone validation, line type | Free (100/mo) |

## Offline Sample Mode

The default `sources.mode: sample` setting runs end-to-end without paid APIs using CSVs in `data/sample/`:

- `properties.csv`
- `business_entities.csv`
- `sec_matches.csv`
- `contacts.csv`

Outputs are written to `data/output/investor_leads_<timestamp>.xlsx`. The workbook includes `All Leads` plus `Hot`, `Warm`, `Cool`, and `Skip` sheets.

## Understanding the Output

The Excel workbook is organized for sales prioritization:

- `lead_score`: 0-100 score from property value, multi-property ownership, business ownership, SEC matches, area income, phone reachability, and recency.
- `score_tier`: Hot, Warm, Cool, or Skip based on the configured score thresholds.
- `call_priority`: Action label for the rep, such as Call First, Call, Research First, Low Priority, or Skip.
- `data_confidence`: Data completeness indicator. High means property, business/entity, phone/contact, and area income signals are present; Medium means property plus at least one enrichment signal; Low means mostly property-only data.
- `lead_summary`: Plain-English explanation of why the lead is or is not interesting.
- `next_action`: The next operational step. For Apollo leads missing an address while ATTOM is enabled, this will prompt address reveal/export before property lookup.
- `interest_tags`: Inferred affinity signals from title, company, Apollo industry, and summary text. These are not verified interests.
- `tech_signal`, `investor_signal`, `networking_signal`: Boolean flags backing those inferred tags.
- Score breakdown columns: `property_score`, `business_score`, `sec_score`, `area_score`, `phone_score`, and `recency_score` show how the total score was built.
- `affinity_score`: Optional, small bonus from inferred affinity tags when enabled in config.

## Configuration

All scoring weights, thresholds, target areas, source mode, SQLite path, and output settings are configurable in `config.yaml`. See `config/config.example.yaml` for documentation of every option.

The implemented scoring model follows the project plan:

- 80-100: Hot
- 60-79: Warm
- 40-59: Cool
- Below 40: Skip

Set `sources.mode: api` to use real adapters. API paths intentionally fail clearly when credentials or paid integrations are missing; sample mode is the supported local/demo path.

## Apollo Integration

Apollo search uses `POST https://api.apollo.io/api/v1/mixed_people/api_search` with the `X-Api-Key` header. Search results may contain obfuscated fields such as `last_name_obfuscated` plus availability flags like `has_email` and `has_direct_phone`, so the pipeline keeps those leads while marking contact fields as missing or obfuscated.

Contact reveal is separate and disabled by default:

```yaml
apollo:
  enabled: true
  per_page: 5
  max_pages: 1
  reveal_contacts: false
  max_reveals_per_run: 0
```

Set `reveal_contacts: true` and a positive `max_reveals_per_run` only when the Apollo account is permitted to reveal contacts and you intentionally want to spend reveal credits.
